## 운영 반영 순서

앱·API·CI·화면 변경을 검증된 커밋으로 묶어 검토한 다음 승인된 운영 반영을 수행한다. 실제 도메인의 READY SHA가 반영 커밋과 일치하는지 확인하고, 홈·최신 칼럼·저자·RSS·사이트맵·이미지·기존 칼럼 리디렉션을 검사한다. 그 후 기존 자동화 한 개의 실행 방식을 격리 작업으로 갱신한다. 이름·일정(매일 00:45/08:45/16:45 KST)·대상 대화·구독 모델·추가 유료 사용 차단·발행 검증 기준은 유지한다.

배포 또는 후속 실행 검증 실패 시 새 생성·게시를 중단하고 해당 시도의 작업 폴더·실패 기록을 보존한다. 원래 체크아웃이나 다른 작업의 잠금을 지우지 않는다. 운영 복구가 필요하면 이 문서의 기존 READY 배포와 SHA를 복구 기준으로 사용하며, 콘텐츠 데이터 변경을 무조건 덮어쓰지 않는다.

모델 로그인 성공, 단위 테스트 통과, 실패를 안전하게 차단한 사실만으로 무인 생성 성공을 주장하지 않는다. 실사용 Core Web Vitals 장기 지표와 무기한 운영 안정성은 이번 로컬 QA만으로 입증할 수 없다.
